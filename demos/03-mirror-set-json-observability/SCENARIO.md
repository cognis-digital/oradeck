# Demo 03 — JSON mirror-set, with a CI/CD override

## Where the data came from

A security-operations team maintains an isolated monitoring network. Their
mirror-set is generated by tooling, so it is emitted as **JSON**
(`mirror-set.json`) — the second on-disk shape `plan --from` accepts:
`{"registry": ..., "images": [...]}`. `destination` / `dest` are accepted as
aliases for `registry`.

The six images are the standard Grafana + Prometheus observability stack at
real, published tags.

## What to expect

`plan --from` auto-detects JSON (leading `{`), reads `images`, and uses the
in-file `registry` as the destination. A `--to` on the command line *overrides*
the in-file value — useful when the same set is staged to a transit registry
before the final air-gapped one.

## Run it

```bash
# Use the registry baked into the JSON.
python -m oradeck plan --from demos/03-mirror-set-json-observability/mirror-set.json

# Override the destination for a staging push (CI variable, etc.).
python -m oradeck plan --from demos/03-mirror-set-json-observability/mirror-set.json \
    --to staging-registry.dmz:5000 --format json
```

## How to act

In a pipeline, store `mirror-set.json` as the source of truth, run `plan` with
`--to $TARGET_REGISTRY` per environment, and drive the resulting `plan[]` array
through copy/push. One file, many destinations, no re-typing.
